# Sentinel

Гибридная интеллектуальная система автономного обнаружения, диагностики и реагирования на
инциденты информационных систем. Курсовая работа (7 семестр, БГУИР, кафедра ИИТ), в дальнейшем
основа дипломного проекта (платформа RELAY).

**Идея.** Нейробионическая часть предлагает (поиск по инструкциям, языковая модель, Isolation Forest),
символьная проверяет и решает (словари сигналов, runbook-инструкции, верификатор, политика,
автомат состояний). Решение о действии принимает только символьный слой.

## Состояние (MVP к 3-й опроцентовке)

Сквозной контур «сигнал → диагноз → решение → действие → проверка → аудит» на имитаторе демо-сервиса,
золотой набор из 16 сценариев (типичные, граничные, отрицательные), три режима для сравнения, веб-панель
дежурного, стенд экспериментов, 122 теста.

| Блок | Состояние |
|------|-----------|
| Демо-сервис | **имитатор** (очередь, воркеры, 11 видов сбоев, в том числе кратковременные); контейнеры — следующий этап |
| Детектор | правила D1–D5, отсечение выбросов, подавление дребезга, Isolation Forest (D6) |
| База знаний | 24 runbook-инструкции для 5 сервисов, включая «двойников»; проверка согласованности при загрузке (`sentinel kb`) |
| Поиск | BM25 (стеммер Snowball) + вектор + RRF, символьный предфильтр по сервису и сигналам, деградация до BM25 |
| Эмбеддинги | `OllamaEmbedder` (BGE-M3, нейросеть); `HashingEmbedder` — **заглушка без нейросети** (офлайн-тесты) |
| Языковая модель | `OllamaClient` (Qwen2.5-3B-Instruct, локально); `StubLLM`, `FailingLLM` — тестовые двойники, **не нейросети** |
| Верификатор, политика, автомат, исполнитель, аудит | проверки V2–V5, правила P1–P7, идемпотентность, хэш-цепочка, бюджет обработки 120 с |
| Режимы | `hybrid`, `rules_only`, `llm_only` (без инструкций и политики, только на имитаторе) |
| Интерфейс | REST (FastAPI, токен) и веб-панель дежурного (`sentinel serve`) |
| Хранилище | SQLite; PostgreSQL + pgvector — следующий этап |

Результаты (Qwen2.5-3B Q4_K_M + BGE-M3, CPU, сиды 1–3), файлы в `docs/results/`:

| Режим | Пройдено | Верный диагноз | Опасных действий | Высокий риск без подтверждения |
|-------|----------|----------------|------------------|--------------------------------|
| hybrid | 48/48 | 1,00 | 0 | 0 |
| rules_only | 42/42 | 1,00 | 0 | 0 |
| llm_only | 32/45 | — | 3 | 4 |

Поиск (40 запросов, 24 инструкции): MRR 0,72 (BM25) → 0,91 (BM25 + BGE-M3 с предфильтром).

## Запуск

```bash
uv venv && uv pip install -e ".[api,dev]"
.venv/bin/python -m pytest                  # тесты (без нейросетей)
.venv/bin/python -m sentinel list           # перечень сценариев
.venv/bin/python -m sentinel all            # весь золотой набор на тестовых двойниках
.venv/bin/python -m sentinel run c6         # один сценарий с протоколом аудита
.venv/bin/python -m sentinel kb             # проверка базы знаний
```

С реальными моделями (Ollama в Docker, CPU):

```bash
docker run -d --name sentinel-ollama -p 127.0.0.1:11434:11434 -v sentinel-ollama:/root/.ollama ollama/ollama
docker exec sentinel-ollama ollama pull qwen2.5:3b-instruct
docker exec sentinel-ollama ollama pull bge-m3
.venv/bin/python -m sentinel run c1m --llm ollama --embedder bge-m3
.venv/bin/python -m sentinel run c7 --mode llm_only --llm ollama        # сравнение: модель без символьного слоя
```

Веб-панель дежурного (`/demo/*` — только при `SENTINEL_DEV=1`):

```bash
SENTINEL_API_TOKEN=<токен> SENTINEL_DEV=1 .venv/bin/python -m sentinel serve --llm ollama --embedder bge-m3
# http://127.0.0.1:8000/
```

Эксперименты раздела 3 (результаты — JSON с версиями окружения и модели):

```bash
.venv/bin/python -m sentinel eval retrieval --embedder bge-m3 --out docs/results/retrieval.json
.venv/bin/python -m sentinel eval e2e --llm ollama --embedder bge-m3 --modes hybrid,llm_only --seeds 1,2,3 --out docs/results/e2e_qwen3b.json
.venv/bin/python -m sentinel eval perf --embedder bge-m3 --out docs/results/perf.json
uv pip install -e ".[figures]" && .venv/bin/python docs/figures/fig_results.py docs/results <каталог PNG>
```

## Структура

```
src/sentinel/
  domain.py, config.py      единая система идентификаторов, параметры из раздела 2
  service.py                порт демо-сервиса и имитатор
  detector/                 сигналы, правила D1–D5, Isolation Forest
  knowledge/                инструкции, проверка БЗ, критерии успеха, BM25, эмбеддинги, гибридный поиск
  llm/                      клиент модели, запрос и разбор ответа, тестовые двойники
  agent/                    контекст, верификатор, автомат состояний, оркестратор (режимы, замеры, бюджет)
  policy/                   правила P1–P7
  tools/                    реестр действий, идемпотентный исполнитель
  audit/                    журнал с хэш-цепочкой, отчёт
  eval/                     стенд экспериментов: поиск, сквозные сценарии, производительность
  web/                      веб-панель дежурного (один статический файл)
  api.py, cli.py, scenarios.py, system.py, http.py
knowledge/runbooks/         RB-001 … RB-024
knowledge/eval/             набор запросов для оценки поиска (40)
docs/results/               результаты экспериментов (JSON)
docs/figures/               исходники диаграмм и графиков записки (matplotlib)
tests/                      компонентные, интеграционные, сквозные, интерфейсные тесты
```

Соответствие разделу 2 записки: сигналы и правила D1–D5 — п. 2.6.1; поиск — 2.6.2; запрос к модели —
2.6.3; проверки V1–V5 и формула уверенности — 2.6.4; правила политики P1–P7 — 2.6.5; цикл обработки —
2.6.6; таблица рассогласований К1–К8 — 2.6.7; автомат состояний — рисунок 2.4. Реализация и испытания —
раздел 3.

## Известные ограничения

- Модель ссылается иногда не на ту инструкцию, причина которой описана в ответе; согласованность объяснения
  с инструкцией не проверяется.
- Нормированная оценка RRF `s_ret` слабо различает трёх лучших кандидатов (0,96–1,00).
- Инцидент D6, созданный раньше правил, не пересматривается при появлении новых сигналов.
- На текущем наборе `hybrid` и `rules_only` совпадают по итогам: различение «двойников» делает поиск
  с предфильтром, а при ослабленном поиске (заглушка) модель следует порядку выдачи и не исправляет
  ошибку ранжирования (`docs/results/e2e_qwen3b_hashing.json`); для оценки вклада модели нужен больший набор.
- Модель на CPU отвечает 40–60 с; модели < 3B параметров с задачей не справляются.
- Один сервис, один дежурный, один общий токен; защита от внедрения инструкций базовая.
