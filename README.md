# Sentinel

Гибридная интеллектуальная система автономного обнаружения, диагностики и реагирования на
инциденты информационных систем. Курсовая работа (7 семестр, БГУИР, кафедра ИИТ), в дальнейшем
основа дипломного проекта (платформа RELAY).

**Идея.** Нейробионическая часть предлагает (поиск по инструкциям, языковая модель, Isolation Forest),
символьная проверяет и решает (словари сигналов, runbook-инструкции, верификатор, политика,
автомат состояний). Решение о действии принимает только символьный слой.

## Состояние (каркас ко 2-й опроцентовке)

Работает сквозной контур «сигнал → диагноз → решение → действие → проверка → аудит» на имитаторе
демо-сервиса, шесть сценариев из записки, REST-интерфейс подтверждения опасных действий, 69 тестов.

| Блок | Состояние |
|------|-----------|
| Демо-сервис | **имитатор** (очередь, воркеры, 7 видов сбоев); контейнеры FastAPI + RabbitMQ + Celery — следующий этап |
| Детектор | правила D1–D5, отсечение выбросов, дедупликация, Isolation Forest (D6) |
| База знаний, поиск | 5 runbook-инструкций (цель — 20–30), BM25 + векторный поиск + RRF |
| Эмбеддинги | `HashingEmbedder` — **заглушка без нейросети** (офлайн-тесты); нейросетевой вариант — `SentenceTransformerEmbedder` (extra `neural`, BGE-M3), в сценариях пока не проверялся |
| Языковая модель | `OllamaClient` (локально); `StubLLM` — тестовый двойник, **не нейросеть** |
| Верификатор, политика, автомат состояний, исполнитель, аудит | реализованы (проверки V2–V5, правила P1–P7, идемпотентность, хэш-цепочка) |
| Хранилище | SQLite (подмножество логической модели); PostgreSQL + pgvector — следующий этап |
| Интерфейс | REST (FastAPI); веб-панель — следующий этап |
| Режимы сравнения | `hybrid`, `rules_only`; `llm_only` запланирован |

## Запуск

```bash
uv venv && uv pip install -e ".[api,dev]"
.venv/bin/python -m sentinel list           # перечень сценариев
.venv/bin/python -m sentinel all            # все сценарии С1–С6 (код возврата 0, если все пройдены)
.venv/bin/python -m sentinel run c6         # один сценарий с протоколом аудита
.venv/bin/python -m pytest                  # тесты
SENTINEL_API_TOKEN=<токен> SENTINEL_DEV=1 .venv/bin/uvicorn --factory sentinel.api:create_app   # REST дежурного (/demo/* только при SENTINEL_DEV=1)
```

Реальная модель (Ollama должен быть запущен, модель загружена: `ollama pull qwen2.5:3b-instruct`):

```bash
.venv/bin/python -m sentinel run c1 --llm ollama --model qwen2.5:3b-instruct
```

Проверка с реальной моделью (Ollama, `qwen2.5:1.5b-instruct`, CPU): ответы по JSON-схеме разбираются, конвейер
не ломается, запрещённые действия не выполняются ни в одном сценарии. Но модель такого размера слаба: в С1 она
возвращает `insufficient_data`, в С2 ссылается на неподходящую инструкцию — система безопасно эскалирует (С1, С2
помечены FAIL, т.к. ожидалось автоисправление). Для осмысленных результатов нужна модель 3–8B.

## Структура

```
src/sentinel/
  domain.py, config.py      единая система идентификаторов, параметры из раздела 2
  service.py                порт демо-сервиса и имитатор
  detector/                 сигналы, правила D1–D5, Isolation Forest
  knowledge/                runbook-инструкции, BM25, эмбеддинги, гибридный поиск (RRF)
  llm/                      клиент модели, запрос и разбор ответа
  agent/                    контекст, верификатор, автомат состояний, оркестратор
  policy/                   правила P1–P7
  tools/                    реестр действий, идемпотентный исполнитель
  audit/                    журнал с хэш-цепочкой, отчёт
  api.py, cli.py, scenarios.py, system.py
knowledge/runbooks/         RB-001 … RB-005
docs/figures/               исходники диаграмм пояснительной записки (matplotlib)
tests/                      компонентные, интеграционные и сквозные тесты
```

Соответствие разделу 2 записки: сигналы и правила D1–D5 — п. 2.6.1; поиск — 2.6.2; запрос к модели —
2.6.3; проверки V1–V5 и формула уверенности — 2.6.4; правила политики P1–P7 — 2.6.5; цикл обработки —
2.6.6; таблица рассогласований К1–К8 — 2.6.7; автомат состояний — рисунок 2.4.

## Известные ограничения каркаса

- Поиск на пяти документах слабо различает кандидатов (оценка `s_ret` почти не расходится) — станет
  информативным при росте базы знаний и нейросетевых эмбеддингах.
- Стеммер для BM25 примитивный (усечение до 6 символов).
- Защита от внедрения инструкций базовая: очистка строк, эвристический сигнал, верификация и политика.
- Один сервис, один дежурный; аутентификация — один общий токен (Bearer), ролевой модели нет.
